## 🚨 Security Incident Response

A structured approach was used when responding to suspected security incidents.

### Incident Response Workflow

```text
Security alert or incident reported
             │
             ▼
Identify affected user/device/system
             │
             ▼
Determine incident scope
             │
             ▼
Collect available evidence
             │
             ▼
Contain the affected system
             │
             ▼
Investigate the suspected cause
             │
             ▼
Remove or remediate the threat
             │
             ▼
Restore normal operation
             │
             ▼
Verify security controls
             │
             ▼
Document the incident
             │
             ▼
Monitor for recurrence
```

Complex incidents were escalated through the appropriate IT and security-management processes.

## 🧪 Security Troubleshooting

A structured approach was used when investigating security-related problems.

### Step 1 — Identify

Determine the affected device, account, application, or network segment.

### Step 2 — Assess

Determine the potential impact and severity.

### Step 3 — Investigate

Review:

* Event logs.
* Security alerts.
* User activity.
* Network connectivity.
* Recent configuration changes.
* Installed applications.
* System status.

### Step 4 — Contain

Where appropriate, isolate or restrict the affected resource.

### Step 5 — Remediate

Remove the cause and restore secure operation.

### Step 6 — Verify

Confirm that:

* The system is operational.
* Security controls are active.
* No obvious indicators remain.
* Required services work correctly.

### Step 7 — Document

Record the incident, action taken, and lessons learned.
